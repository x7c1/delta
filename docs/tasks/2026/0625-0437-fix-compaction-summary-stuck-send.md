# fix(attribution): classify /compact summary as its own role so pending sends are not stuck

## Overview

When a Claude Code session is resumed and `/compact` runs, Claude Code writes
a single synthetic line to the JSONL transcript with `type: "user"` and a
top-level boolean `isCompactSummary: true`, carrying the previous-conversation
summary it just generated. Delta currently does not read the
`isCompactSummary` field at all, so that line is treated as an ordinary user
turn by the attribution pipeline. Two concrete consequences observed in
dogfooding:

1. The outstanding `dispatched` send that triggered (or coincided with) the
   compaction is never matched against this synthetic line — the summary text
   does not equal the user's prompt text — so `SendMatched` is not emitted and
   the send remains `dispatched` forever. In the UI this surfaces as a pending
   message that never clears.
2. The attribution state's `carry_thread` is reset to the main thread because
   the line is taken to be a fresh human turn, which corrupts thread
   attribution for any subsequent message.

The same shape (`type: "user"` + boolean flag) is already handled for
`isMeta` and `isApiErrorMessage` in
`backend/crates/gateway/delta-transcript/src/parse/raw_line.rs`, but
`isCompactSummary` is not on `RawLine`.

This task takes **approach A** from the design discussion: extend the
`Role` enum in `backend/crates/domain/delta-model/src/role.rs` with a
dedicated `CompactSummary` variant (a sibling of `User`/`Assistant`/`System`/
`Meta`/`Other`) and route `isCompactSummary: true` lines into it at parse
time. A new role variant — rather than folding into `Role::Meta` — is chosen
to preserve a semantic distinction the UI and future tooling will want
(e.g. rendering a "session compacted here" marker, or correlating
compaction with token / latency stats); collapsing it into `Meta` would
discard information that is non-trivial to recover later.

### What changes

1. **`RawLine`** (`backend/crates/gateway/delta-transcript/src/parse/raw_line.rs`)
   — add an optional field:

   ```rust
   /// Set on the synthetic user line Claude Code writes when /compact runs,
   /// carrying the previous-conversation summary. Not a human-authored
   /// turn; classified as [`Role::CompactSummary`] so attribution skips it.
   #[serde(rename = "isCompactSummary")]
   pub is_compact_summary: Option<bool>,
   ```

2. **`Role`** (`backend/crates/domain/delta-model/src/role.rs`) — add a
   `CompactSummary` variant. Update `as_str` ("compact_summary"), `parse`
   (round-trip), and the existing `role_round_trips_through_string` test
   list. The new variant must compile cleanly against every existing
   exhaustive `match` on `Role` in the workspace (the compiler enforces
   coverage; for current call-sites the right behaviour is usually
   "treat like `Meta`" — i.e. not a human turn, not an assistant
   message — but each site must be reviewed individually rather than
   blanket-routed).

3. **Parser → role classification** in
   `backend/crates/gateway/delta-transcript/src/parse/` — wherever
   `is_meta` currently overrides a `type: "user"` line into `Role::Meta`,
   add the analogous override: if `is_compact_summary == Some(true)` then
   classify the line as `Role::CompactSummary` (taking precedence over
   the default `User` classification, and over `Meta` if both flags
   somehow coincide).

4. **Attribution** (`backend/crates/domain/delta-attribution/src/attribute.rs`)
   — ensure `is_human_turn` returns `false` for `Role::CompactSummary`,
   matching the existing exclusion logic for interrupts /
   task-notifications. `carry_thread` must be preserved (not reset to the
   main thread) when a compact-summary line is encountered, and no
   `SendMatched` effect must be emitted for it.

5. **DB / wire compatibility** — `Role` is persisted as a lowercase
   string. The new label `compact_summary` is purely additive: existing
   rows never carry it, so no migration is required, but the wire/UI
   types that mirror `Role` (if any are generated by `make gen`) must be
   regenerated and committed in the same PR.

## Out of scope

- Re-purposing `SessionStart(source=compact)` to roll outstanding
  `dispatched` sends back to `queued`. This is a sensible follow-up for
  the case where compaction lands as the literal last transcript line
  with no subsequent user prompt, but it is a separate change with its
  own design surface (it touches
  `backend/crates/domain/delta-usecase/src/interactor/hooks/on_session_start.rs`
  and the `session_start_clear_and_compact_are_noops` test, which is
  currently a deliberate no-op).
- Surfacing a "session compacted here" marker in the conversation view.
  The new `Role::CompactSummary` makes this trivial to add later, but
  the UI work is intentionally deferred.
- Promoting `isApiErrorMessage` to its own role variant. Same shape,
  same argument, but out of scope for this PR.
- Frontend / wire surface changes beyond regenerating bindings that the
  build already requires. No new UI behaviour.
